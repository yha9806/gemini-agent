# Telemetry Failed Governance Design

Date: 2026-06-10

## Scope

Add local governance commands for telemetry events that remain in `queue/failed` after bounded recovery attempts. The immediate production need is to stop unrecoverable historical failures from making `telemetry doctor` look blocked while keeping enough local audit trail to explain what happened later.

This feature does not resend telemetry, reveal raw prompts or responses, delete data permanently by default, call the network, change receiver ingest behavior, or treat archived failures as successful sends. It only gives operators a safe way to inspect failed-event shape and move explicitly selected failures out of the live failed queue.

## Decision

Implement a new failed-governance command group:

```bash
gemini-agent telemetry failed inspect [--global] [--reason <reason>] [--limit <n>] [--json]
gemini-agent telemetry failed archive [--global] --reason <reason> [--dry-run|--write] [--batch-size <n>] [--note <text>]
```

`inspect` is read-only and aggregate-first. It reports failed reason counts plus bounded safe descriptors for failed events. It is intended to answer "what kind of failures are left?" without exposing raw event content.

`archive` is a local-only lifecycle transition. It moves matching failed event files from `queue/failed` to `queue/resolved-failed` under the queue lock. `telemetry doctor` continues to count live `failed` events, but it does not count `resolved-failed` as delivery-blocking.

## Operator Flow

The intended operator flow is:

```bash
gemini-agent telemetry doctor --global --json
gemini-agent telemetry failed inspect --global --json
gemini-agent telemetry failed archive --global --reason http_403 --dry-run --batch-size 1
gemini-agent telemetry failed archive --global --reason http_403 --write --batch-size 1 --note "unrecoverable historical paused-deployment failure"
gemini-agent telemetry doctor --global --json
```

Operators should use `retry-failed` first when the failure is plausibly recoverable. `archive` is for failures that remain after recovery is not possible or no longer worthwhile.

## Architecture

Keep the feature inside the telemetry queue subsystem:

- `src/telemetry-queue.mjs` owns failed-event scanning, safe descriptor creation, and archive movement.
- `src/cli.mjs` owns argument parsing, local/global scope resolution, output format, and help text.
- `src/telemetry-doctor.mjs` continues to read live queue summaries and should ignore `queue/resolved-failed`.
- Tests live in `test/telemetry-queue.test.mjs` and `test/cli.test.mjs`.

The queue module should expose two focused helpers:

```js
inspectFailedTelemetryEvents({
  cwd,
  reason,
  limit,
})

archiveFailedTelemetryEvents({
  cwd,
  reason,
  batchSize,
  dryRun,
  note,
})
```

Both helpers return allowlisted aggregate data only. They must not return event ids, batch ids, raw prompts, raw responses, request payloads, media filenames, or filesystem paths.

## Queue Layout

Current failed queue:

```text
.gemini-agent/telemetry/queue/failed/<batch-id>/
  reason.json
  event_*.json
```

New resolved queue:

```text
.gemini-agent/telemetry/queue/resolved-failed/<resolution-bucket>/
  reason.json
  resolution.json
  event_*.json
```

`resolution-bucket` must be generated by the program, not copied from user input. Use a safe format such as:

```text
resolved_<YYYYMMDD>_<milliseconds>_<random-uuid>
```

The archive helper must use the same secure directory and file modes as the existing queue. It must never use `--reason` or `--note` directly in a path.

## Inspect Output

`inspect` returns:

- `ok`
- `scope`
- `storage_cwd`
- `reason_filter`
- `failed_event_count`
- `failed_batch_count`
- `reason_counts`
- `events`

Each `events[]` item may include only:

- `reason`
- `command`
- `model`
- `status`
- `schema_version`
- `created_day`
- `prompt_bytes`
- `response_bytes`
- `media_item_count`
- `retryable_hint`

Field values are normalized through safe diagnostic label functions. Long strings are truncated to a small diagnostic length. Missing or malformed values become `unknown`, `0`, or `null` depending on type.

`inspect` must default to a small limit such as `20`. It may report aggregate counts for all failed events, but detailed descriptors must respect `--limit`.

## Archive Behavior

Dry-run:

1. Resolve telemetry scope and storage cwd.
2. Scan failed batch directories.
3. Match failed batches by sanitized reason.
4. Count candidate event files, bytes, and matched batch count.
5. Return aggregate preview and a safe next command.

Write:

1. Resolve telemetry scope and storage cwd.
2. Do not require endpoint config, token env, or network access.
3. Acquire `withTelemetryQueueLock`.
4. Re-scan failed batches while holding the lock.
5. Move at most `batchSize` matching failed event files to a newly created `resolved-failed` bucket.
6. Copy or write reason metadata for the resolved bucket.
7. Write `resolution.json` with sanitized reason, sanitized note, count, and timestamp.
8. Preserve the original failed batch directory when it still has event files.
9. Remove an original failed batch directory only when no event files remain.
10. Recompute `queue_bytes` from pending files and save queue state.
11. Return aggregate counts and a next command to run `telemetry doctor`.

`archive` does not decrement lifetime failure counters. It only changes the live failed queue state.

## Privacy Boundary

Allowed output:

- Scope and storage cwd.
- Sanitized failure reason.
- Dry-run/write mode.
- Event and batch counts.
- Byte counts.
- Safe descriptors listed in this design.
- Safe next command.

Forbidden output:

- Event ids.
- Batch ids.
- Raw prompt text.
- Raw response text.
- Request payloads.
- Response candidates.
- Tool calls.
- Media filenames.
- Failed directory names.
- Event file paths.
- Unsanitized notes.

The implementation should use an allowlist serializer for inspect and archive results. It should not stringify whole event objects.

## Reason And Note Handling

`--reason` uses the same sanitization as `retry-failed`, so operators can target existing reasons such as `http_403`, `unauthorized`, or `unknown`.

`--note` is optional. It is local metadata only. It must be sanitized to a short diagnostic string, for example 160 characters. Empty notes become `null`. The note must never be used in filenames or shell commands.

## Error Handling

- Missing `--reason` for `archive`: fail before reading queue state.
- Both `--dry-run` and `--write`: fail argument parsing.
- Invalid `--batch-size`: fail argument parsing.
- Invalid `--limit`: fail argument parsing.
- No matching failed batches: return `ok: true`, zero counts, and no mutation.
- Failed batch with missing or malformed `reason.json`: classify as `unknown`.
- Malformed event file: include it in counts and describe it as `command: "unknown"` without throwing.
- Lock contention during write: fail without partial movement.
- Move failure after partial movement: surface the filesystem error. A subsequent inspect must reflect actual state.

## Concurrency

All write-mode scanning, bucket creation, event movement, metadata writing, cleanup, and queue state updates happen under `withTelemetryQueueLock`. Dry-run and inspect may scan without the lock because their output is advisory.

The command should remain bounded by `--batch-size`; broad archive work should be repeated in small batches instead of holding the lock for a long time.

## Doctor Semantics

`telemetry doctor` already reports live queue states from `pending`, `inflight`, `sent`, `failed`, and `quarantine`. It should continue to use that live set. `resolved-failed` is not delivery-blocking and should not be included in `failed_events`.

A later summary command can expose resolved-failed counts for audit. This design only requires doctor to stop treating archived events as live failed events.

## Testing

Use TDD with focused queue and CLI tests.

Required queue tests:

- `inspectFailedTelemetryEvents` returns reason counts and bounded safe descriptors.
- `inspectFailedTelemetryEvents` filters by sanitized reason.
- `inspectFailedTelemetryEvents` does not return event ids, batch ids, raw prompt text, raw response text, media filenames, directory names, or paths.
- `archiveFailedTelemetryEvents` dry-run reports matching counts without moving files.
- `archiveFailedTelemetryEvents` write mode moves only matching reason events into `resolved-failed`.
- Partial archive preserves original `reason.json` and leaves remaining failed events recoverable.
- Empty original failed batch directories are removed only after all event files move out.
- Malformed or missing reason metadata is handled as `unknown`.
- Archive path generation resists traversal-like reason and note inputs.
- Write mode succeeds without telemetry token env or endpoint config.
- Write mode respects queue lock contention.

Required CLI tests:

- `telemetry failed inspect --json` prints aggregate-only JSON.
- `telemetry failed inspect --reason http_403 --limit 1 --json` filters and bounds descriptors.
- `telemetry failed archive --reason http_403 --dry-run` prints aggregate-only preview.
- `telemetry failed archive --reason http_403 --write --batch-size 1` moves a bounded event to resolved-failed.
- `telemetry failed archive` rejects missing reason.
- `telemetry failed archive` rejects conflicting mode flags.
- `telemetry failed archive` does not require token env in write mode.
- `--global` targets home telemetry storage.

Run targeted tests first:

```bash
node --test test/telemetry-queue.test.mjs test/cli.test.mjs
```

Then run full verification:

```bash
npm test
```

## Acceptance Criteria

- Operators can inspect live failed telemetry without exposing raw content or identifiers.
- Operators can archive explicitly selected failed events in bounded dry-run/write batches.
- Archived failures no longer block `telemetry doctor` delivery health.
- Archive is local-only and does not require token env, endpoint config, or network access.
- Queue state remains consistent after partial archive.
- All output is aggregate-only or allowlisted safe descriptors.
- Targeted tests and full `npm test` pass.

## Self-Review

- No open implementation choices remain.
- The feature is scoped to failed-event governance, not broad raw reveal/export/delete.
- The archive command preserves auditability instead of deleting files.
- The design avoids token-env deadlock for auth-related failures.
- The privacy boundary is allowlist-based and excludes identifiers, raw content, paths, and media filenames.
